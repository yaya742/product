# 在场｜以理解、合作与办成为中心的 Harness

设计日期：2026-09-12。

这不是对当前应用源码的验收报告，也不是已经运行成功的新产品。依据是本轮上传的《在场的记忆讨论(2).txt》和《在场-Harness-审查研究与语义重构包(1).zip》，以及本轮核查的一手研究和官方文档。ZIP 是上一轮研究设计、源码节选和旧探针记录的交付包；不能把其中的历史运行结果称为本轮重新验证。

- `04-研究依据与决策记录.md`：附件证据位置、一手来源、采用内容及推断边界。

## 本轮最重要的增量

上一版已经把关键词路由否定了，也已经决定使用 Hermes。这里不把这两点重新包装成发现。

最新 ZIP 也已经提出共同语境、请求覆盖与修复，不能误称缺失。本轮进一步展开的是：主模型获得判断权之后，怎样持续接住用户没有一次说完的意思；怎样找到它尚不知道需要找的记忆；怎样不漏掉混合消息中的实际委托；怎样在用户说“你理解错了”之后改变后续判断；怎样把有能力调用工具变成确实办成事情；怎样避免安全和工程结构再次挤掉自然交流。

**一句话：用一个持续负责的主 Agent 理解和推进，用证据、工作状态和真实环境约束它；不让分类器替它理解人，也不让“交给模型”成为无人负责的借口。**

所有组件名、数据对象名和 RPC 名称，除明确标注的上游接口外，均为本设计的职责命名，不是声称第三方已经提供现成 API。
