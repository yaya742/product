# 校园地图 V2

从在场窗口右上角的校园地图图标进入，也可以打开对话中的地图结果卡。返回后，对话、输入草稿和地图视野保留。

## 使用

- 拖动平移，滚轮缩放；Shift + 拖动、右侧旋转按钮或 Q / E 旋转。N 回北，0 查看校园。键盘快捷键只在地图获得焦点时生效。
- 点击建筑轮廓或搜索后按 Enter，选择目的地。悬停只显示名称，不更改目的地。
- “两点路线”先选起点 A，再选终点 B；之后点选只更换 B。可以更改起点、交换两端、清除，或回到本机位置模式。
- 定位使用这台 Windows 电脑的系统位置服务。误差、过期和范围外状态如实显示；未接入手机位置。位置到路网的通行连接不明确时，选择实际所在且有已知入口的建筑作为起点。
- “查看全路线”考虑当前旋转、窗口尺寸和信息条遮挡。地图操作会立即中断自动镜头。

## 数据与覆盖

本次重新取得 OpenStreetMap 矢量数据，源数据库时间为 **2026-09-10 00:56:48 UTC**。查询范围是经度 120.060–120.101、纬度 30.293–30.326，覆盖紫金港与望月公寓（桂花苑）周边。与查询边缘相交的完整建筑保留稳定对象 ID；范围以外没有数据不代表现实中没有道路。

当前数据包含 **533 栋可选建筑**、608 个可搜索地点（含 10 个核心地标和官方名称别名）、67 个合格的已标注入口。其中 37 个入口与步行图直接相连，25 栋建筑具备已知入口连接。图中有 5,865 个节点、6,525 条道路边。并非校园所有现实建筑和入口都已被 OSM 完整收录；当前公开官方名称层有 379 条记录，其中 127 条已按 25 米空间阈值或同名空间匹配映射为搜索别名，241 条保持未绑定，避免误绑。望月公寓的范围可定位、选择；它的入口连接缺失，因此不会绘制假路线。

建筑轮廓、孔洞、多部件、水系和道路保留源几何。入口只有在建筑边界与道路使用同一个源节点时才连接，不进行“最近道路”吸附。受限入口、关闭节点、时间限制未能解释的道路，以及未标桥的穿水连接和穿墙连接，不进入步行图。地图显示用 Web Mercator，路线长度使用 WGS84 经纬度上的球面距离，单位为米；不从屏幕像素计算距离。

路线比较全部合格起终点入口，以已记录路段长度之和为目标。**“最短”只对当前已知图成立**，不保证未收录道路、实时门禁、施工或现场通行。未知入口、不可达、范围外和数据错误分别返回原因，均不降级成直线。

来源资格、官网检查和许可说明见[数据来源](assets/map-v2/SOURCE.md)。地图保留 OSM 署名；原始地理数据、核心地标清单、官方名称交叉索引、处理结果和 ODbL 许可随包提供。求是大道使用当前浙大公开 WFS 的名称锚点，不把官方 2.5D 面当作可导航道路；西操场使用 OSM 的“紫金港西田径场”真实几何并补充常用别名。没有复制官网栅格或 2.5D 热点作为建筑占地。

## 运行与重建

```powershell
npm ci
npm run dev
npm run build
npm start
npm run package
```

日常使用 `release/win-unpacked/在场.exe`。单文件版本为 `release/Zaichang-0.3.0-Windows.exe`。

离线重建当前地理数据，不访问网络：

```powershell
npm run map:import -- assets/map-v2/source.osm.json.gz
```

需要主动更新数据时，执行有界下载脚本，再构建并重启软件。应用启动不会请求 Overpass，也不会自动重新抓取官网。

```powershell
node scripts/fetch-map-v2.mjs
npm run build
```

仅当本机代理不可用且直连正常时，可以给下载脚本加 `--direct`。它只改变该次下载，不修改系统代理。

## 验证

```powershell
npm test
npm run test:map:core
npm run test:map
npm run test:desktop
npm run test:connection
node tests/package.mjs
node scripts/check-project-docs.mjs
```

地图核心测试检查独立小图最优值、多入口、方向限制、孔洞、多部件、源节点连接、陌生端点、旧响应丢弃、定位质量和灰阶约束。桌面测试使用隔离资料目录运行真实 Electron；受控定位与延迟响应明确标为模拟，不能替代真机定位证据。

另外使用本机 Gurobi 13.0.2 对真实入口集合建立独立的最小费用单位流模型，与应用结果比较。它只参与开发验证，不是软件运行依赖；许可探针通过后执行 `python scripts/verify-map-optimality.py`。验证对象和结果在 `artifacts/map-v2/route-cases.json` 与 `route-optimality.json`。

最新状态与证据入口以[项目导航](PROJECT-NAVIGATION.md#status)为准。最终地图审计见 `artifacts/map-v2/final-audit.json`；桌面报告和正常速度录像位于 `artifacts/map-v2/desktop/`；真实 Windows 定位的脱敏记录为 `artifacts/map-v2/native-location.json`。没有进行实地门禁调查，也没有把浏览器或受控触控输入称为手机真机验证。
