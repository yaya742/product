# 项目使命与受保护原则

这是开发在场的指导，不是学生 Profile、运行时系统提示词或新增操作权限。

## 输入与读取

先确认当次用户任务、工作范围和要改变的对象。仅在涉及下列原则的取舍时读完本入口。当前策略、代码事实、未接入模块和证据编号，按需查唯一的[项目导航](../../../PROJECT-NAVIGATION.md)，不要从旧会话补出模块或授权。

## 为什么存在

帮助在校学生在校园事务、个人目标与日常条件交织时，获得可信的查询结果、可理解的判断和可调整的下一步，减少整理与反复核对的负担。帮助学生掌握自己的生活；不是替他们建立一个无法质疑的人设，或以督促之名剥夺选择。

以下 P1–P5 是对用户明确要求的可检查转述，不是现有代码已达标的宣告。普通迭代必须保护；产品负责人可以按“重大修订”规则改变使命。判别原则时问：即使模型、学校、地图供应商、界面和全部代码都换掉，它是否仍应保护用户？否则归入策略、方法或实现。

## P1 · 用户保有决定权与明确授权

- **保护什么、为什么：** 学生能理解、选择、更正、拒绝和撤回适当范围的安排与数据使用；便利不能来自用户不知道系统在做什么。
- **何时违背：** 把查询授权推成预约授权；按性格推断同意；把建议默认为已接受；弱化必要控制来减少界面元素。
- **冲突处理：** 先界定当次任务的授权，再在范围内减少重复确认。已有明确授权可继续使用；未获授权的外部动作先准备可审阅对象。拒绝某项数据访问不应被解释为拒绝全部帮助。

## P2 · 只使用与任务相称、属于正确用户的数据

- **保护什么、为什么：** 有用的个性化与数据用途、访问和保留边界并存；资料归入 Profile 并不代表所有任务都能读取。
- **何时违背：** 为可能有用而默认采集；每次把完整 User、成绩、健康史和聊天全量注入；跨用户复用记录；把凭据当模型上下文。
- **冲突处理：** 先说明本任务最少需要什么及其访问依据，缺信息时缩小结论或补问。业务分类与隐私限制分别判断；新用途、撤回或用户切换时重新检查边界。

## P3 · 事实、来源、新鲜度与行动状态保持真实

- **保护什么、为什么：** 用户能够分清学校记录、自述、推断、示例、建议及实际执行，避免依据不存在或过期的信息做决定。
- **何时违背：** 把模块名当已实现；把独立完成当已接入；把静态课表当逐次安排；把本地完成勾选当官方体育计次；把未知预约回执当成功。
- **冲突处理：** 保留业务域的权威来源与适用范围，冲突资料并列说明，不由摘要或偏好改写事实。不确定时展示缺口和可行下一步，不用流畅文案制造确定性。

## P4 · 理解用户应允许变化、纠正与有边界的遗忘

- **保护什么、为什么：** 人的临时状态、长期偏好、目标与自愿提供的倾向不同，不能因一次记录而永久定型。
- **何时违背：** 把“今天不想跑”当长期厌恶；从成绩推人格；人格覆盖当前意愿；界面删了偏好，旧摘要仍把它当有效偏好使用。
- **冲突处理：** 先归属到正确对象，再维护来源、生效和替代关系。明确偏好与当前指令优先于推测倾向；纠正和遗忘须检查受影响的派生理解，并说明原始记录、已发送内容和删除范围的实际边界。

## P5 · 简洁要降低人的负担，并保留可恢复的体验

- **保护什么、为什么：** 用户不必理解内部模块才得到帮助；不同设备、能力和使用情境下都能看清内容、操作和状态。
- **何时违背：** 隐藏错误、来源或权限来留白；让用户反复重输；停止、切换或重试吞掉草稿；为视觉效果强迫等待；将一种学习时长或布局套给所有人。
- **冲突处理：** 先保住核心任务的可理解性、控制与恢复，再选择表达方式。以具体任务、实际画面和交互证据判断舒适度，不以“极简、苹果感、丝滑”代替可检查的结果。

## 非目标与四层边界

不建设供模型任意读取的私人数据总仓；不让摘要成为第二份课表或成绩表；不把自动化次数、数据量或固定人格分类本身当用户价值；不承诺无依据的全知、实时和全部成功。

- 本入口维护 **使命与 P1–P5**。
- [导航的当前范围](../../../PROJECT-NAVIGATION.md#当前范围)维护当前桌面 Agent 的职责和阶段范围。
- [product-design](../product-design/SKILL.md)维护有适用条件的方法。
- 技术栈、字段、目录、配色、具体尺寸和服务供应商均是可替换实现。换实现本身不等于修改使命。

## 重大修订与完成标准

若要改变使命或 P1–P5，明确提出旧条目、新条目、原因、对用户及现有承诺的影响、新旧对应关系和缓解办法，由产品负责人确认；不能通过追加一句例外暗改旧原则。若当次用户已明确批准该变更，记录依据即可，不重复请求许可。策略变更尊重当前明确指令和当次授权，不把普通实现选择自动升级为原则审批。

更正错字、链接或保持含义的文字整理不属于重大修订；改变保护范围、优先关系、例外或用户承诺才适用上述流程。

一次取舍完成时，应能说明：改变属于哪层；保护了哪些用户利益；与当前要求有无冲突；事实与缺口的来源；哪些还只是建议。无法证明实现满足原则时，在导航中保留差距，不能改写事实来制造符合。
