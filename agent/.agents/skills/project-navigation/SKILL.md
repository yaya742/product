# 项目导航与变更定位

本入口规定定位方法；会变的路径、职责映射、状态和缺口只维护在[PROJECT-NAVIGATION.md](../../../PROJECT-NAVIGATION.md)。它是开发导航，不是运行时路由、用户数据库或授权系统。

## 必要输入

当次任务与允许的读写范围、项目工作区、要解决的问题、已授权的独立模块路径（如有）。路径缺失不阻塞其他工作：记录“用户报告独立完成／未提供路径／未核实”，不能扫描其他项目或重建一个替代模块。

## 定位流程

1. 从项目 [AGENTS.md](../../../AGENTS.md) 和导航的“变更入口”开始，按任务读取相关章节。先区分用户明确要求、已确认决策、实现事实、新建议和缺证据推断。
2. 先找概念职责及事实所有者，再沿“UI → Bridge/IPC → 判断或工具 → 接入／存储 → 相关测试”读取必要路径。同一文件承担多个职责不意味着要物理拆成多个服务。
3. 对照当前文件和调用方核实索引；路径存在、读过实现、有测试源码、有历史报告、本次运行验证是不同证据。不要从文件名、旧会话或测试标题推断功能完成。
4. 同时记录 A **实现／集成程度** 和 B **运行状态／证据时间**。独立模块可运行不代表本产品接入；代码有天气工具不代表当前已授权或联网成功。
5. 对 User 相关任务先查[对象边界](../../../PROJECT-NAVIGATION.md#user)，说明需要读什么、不该读什么。账号、凭据、授权与多用户隔离是横切边界，不并入模型 Profile。
6. 输出最小变更面、受影响的状态所有者和派生结果、所需验证。若未获实现授权，到定位和契约为止；本 Skill 不授权连接账号、生产写入或迁移。

## 索引更新

新增、删除、移动自有文件或改变职责时，在同一变更更新导航的对应条目、状态和证据时间。索引外出现文件先核实再补录，不为让校验通过随意排除。依赖、构建产物和二进制可按导航中声明的目录归组；不得把实际个人运行库当公开索引内容。

保持一份路径真相：其他 Skills、README 和设计记录链接导航，不另列一棵目录。设计记录中的旧路径、数值和截图是特定版本证据，不能覆盖导航中的当前事实。

## 完成标准

交接结果应包含：正确入口与调用关系、职责及数据所有者、A/B 状态、事实与规划的区别、最少缺失信息、适合此次范围的验证及未执行项。运行 `node scripts/check-project-docs.mjs` 检查引用与索引覆盖；它只验证文档，不运行 App、不查账号，也不能证明业务功能正确。

重大使命取舍再按需读 [project-foundations](../project-foundations/SKILL.md)；体验设计或评审再读 [product-design](../product-design/SKILL.md)。不要为了路由加载全部资料或新建地图、天气、User 等空 Skill。
